# RTOS 与寄存器实验室

双击 **RTOS与寄存器实验室.html** 即可离线运行。也可打开 index.html（保留同目录 JS/CSS）。根目录的 **学习导航.html** 汇集本项目所有实验入口。

本模块面向已有 C/C++、Linux 基础、准备开发 Zynq PS 软件的学习者。浏览器运行确定性的 JavaScript 教学模型，不运行真实 FreeRTOS 内核，不访问板卡。屏幕中的时间是逻辑时间，不能作为中断延迟、调度开销或硬件实时性的测量。

## 使用方式

1. 选择“寄存器与中断”或“RTOS 任务调度”，再选择具体场景。
2. 先回答左侧预测题。答题不会阻止你操作实验。
3. 点击“下一步”，观察状态快照、概念代码和累计事件。播放、进度条、上一步可重放整个过程。
4. 点击“切换对照场景”，比较错误用法与正确用法。
5. 调度实验可修改观察窗口和采集任务每轮工作量。修改后点击“生成 / 重置”才生效。
6. “到结果”显示完整结论；结果在回放结束之前隐藏。导出 JSON 包含完整模型、配置和当前游标，未来事件属于模型预测。

## 寄存器与中断：六组实验

| 场景 | 要观察的区别 |
|---|---|
| 正常中断处理 | 外设置位 → IRQ → ISR 读取状态 → 清源 → 控制器完成 → 任务通知与运行 |
| 未清除中断源 | 完成控制器 EOI 不等于清除外设；电平源仍有效会重新触发 |
| 中断被屏蔽 | 状态可以已经锁存，但 IRQ 输出被屏蔽；恢复使能后检查是否触发 |
| 正确清除 W1C | 状态为 3，写 DONE=1 后剩下 ERROR=2 |
| W1C 读改写陷阱 | 读出 3 后 OR 1 仍为 3；写回清掉两位，可能丢失未记录错误 |
| 写只读寄存器 | 虚拟 ID 寄存器忽略写入；真实硬件必须查手册 |

RW 表示读写；RO 表示只读；W1C 表示写 1 清除。低八位格子只是显示辅助，十六进制值显示完整 32 位。偏移和外设均为教学设定，不是 Zynq 真实寄存器表。

本模型使用锁存状态与电平触发 IRQ。源状态、外设使能掩码、控制器活动状态和 ISR 上下文分开表示。中断控制器抽象操作不构成通用 GIC 初始化教程；边沿触发、共享中断、嵌套中断及同位新事件竞争没有展开。只读写入被忽略是本虚拟器件的规定，不适用于所有设备。

## RTOS 调度：六组实验

| 对照 | 观察重点 |
|---|---|
| 阻塞等待 / 忙等 | H 等外部事件时，M、L 是否有机会运行；外部 IRQ 仍可触发 |
| 优先级反转 / 优先级继承 | L 持锁，H 请求锁而阻塞，M 抢占 L；继承使 L 临时提高有效优先级 |
| 相对延时 / 固定周期 | 完成工作后延时会把工作时长累积进周期；按绝对释放时刻安排则不同 |

固定优先级、单核、高数值优先级先运行。互斥实验仅一把锁；不是 FreeRTOS 多锁继承、SMP 或完整内核的模拟。步骤分为边界事件与执行时间片，同一逻辑时刻可能有多步。运行区间步骤的任务表是区间开始时的快照；边界事件的快照在动作后生成。时间线中的 actor 表示执行者；即便 actor 为 H，阻塞动作后的任务状态也可能已是 blocked。

周期实验的工作量小于周期，且没有其他任务干扰，不能据此推断实际系统不会超期。H/M/L 命名表示本实验里的优先级关系，不是具体工作岗位或真实任务名称。

## 从动画对应到真实代码

- **Linux MMIO**：通过对应映射与 readl/writel 等访问器操作寄存器。普通内存指针操作不能代替所有平台的 I/O 访问要求。
- **裸机 / RTOS**：使用实际平台 BSP 和器件手册规定的寄存器接口。读清除、写 1 清除等语义必须逐项确认。
- **中断 → 任务**：根据 RTOS 移植层允许的中断优先级，使用相应 FromISR 接口，必要时请求 ISR 退出后的任务切换。通知与直接调用任务函数是两回事。
- **互斥与同步**：FreeRTOS 互斥锁具备基本优先级继承；用于事件同步的二值信号量没有这一机制，且互斥锁不能在 ISR 中等待。
- **周期任务**：理解 vTaskDelay 与 xTaskDelayUntil 的相对/绝对唤醒语义；真实延迟仍受 tick 分辨率、抢占和超期影响。
- **volatile 的边界**：不能替代原子操作、同步、内存屏障或 DMA 缓存一致性维护。

## 自测

1. ERROR 与 DONE 同时置位时，怎样只清除 DONE？写出总线实际写入值。
2. 外设状态为 DONE、IRQ_ENABLE 为 0，CPU 没进中断能否证明设备没完成？
3. 为什么给中断控制器发送 EOI 后，还可能马上再次进入 ISR？
4. H 阻塞时，为什么 M 可以执行？H 忙等时结果有什么不同？
5. 优先级继承改变的是谁？什么时候应恢复基础优先级？
6. 工作 2 单位、延时 5 单位，相邻开始时间间隔是多少？固定周期 5 又是多少？

参考答案：1) 写 1；2) 不能；3) 电平中断源可能仍有效；4) 阻塞任务不参与就绪调度，忙等任务仍可运行；5) 提升持锁者，本模型在释放唯一互斥锁后恢复；6) 分别为 7 与 5（本实验无干扰条件）。
